# Prompt for a recurring Codex task

```text
Open X in the available signed-in Mac browser and search the latest posts with the query `(\"MiniMax H3\" OR \"Hailuo 3.0\" OR \"MiniMax-H3\") filter:native_video -filter:replies`. Discover original MiniMax H3 / Hailuo 3.0 video examples from the last 24 hours and follow docs/DISCOVERY_WORKFLOW.md exactly. Automatically publish clear cases whose original post explicitly identifies an H3-generated native video, has a clear author/source and playable media, and is not an obvious repost, bulk advertisement, tutorial/news clip, or unrelated output. Deduplicate against candidates and public cases. For every clear case, review the actual video and write a concise bilingual content title and summary describing the visible subject, central action/event, or clearly evidenced experiment. Store these under `editorialCopy` with an evidence basis. Never put `@handle`, MiniMax H3, source, date, generation mode, or templates such as “社区视频案例 / 本地生成案例 / Model Comparison by @handle” in a public title; author handles belong only in attribution fields. If the caption does not establish the depicted content, inspect at least beginning, middle, and end frames; if reliable content evidence is still missing, keep the item in the candidate queue and do not invent copy. Download the highest-quality public MP4, upload it to the existing private Railway video bucket, set `mediaUrl` to `/media/{case-id}.mp4`, cache its poster, preserve the original `sourceUrl` for the X icon, then add it to data/cases.json and remove it from the queue. Never publish an X-only embed or a case whose hosted video is missing; keep download/upload failures in data/candidates.json with a factual reason. Leave only genuinely ambiguous items in data/candidates.json. Copy prompt text only when the original source post visibly publishes the complete exact text; otherwise record `prompt: null` with provenance `not-published`. Never generate, complete, translate into an alleged original, rewrite, adapt, reconstruct, reverse-engineer, summarize, or decompose a missing prompt, and never infer a hidden workflow from the finished video. Use `mimo-v2.5-pro` only to classify public text and metadata when the local `MIMO_API_KEY` is configured; use `mimo-v2.5` only for limited eligibility/media verification of ambiguous videos. Keep all bucket/API credentials server-side and never print or commit them. Run validation, tests, and the production build; after success commit and push the related changes to GitHub, allow Railway to auto-deploy, and verify the deployment plus a ranged video response. Report published cases, remaining ambiguous items, public-prompt count, commit, and deployment status. If X is unavailable or logged out, report the blocker without inventing cases.
```

Before the normal validation sequence, run `npm run sync:stats`. This refreshes the canonical statistics JSON, the public website snapshot, and both README summary blocks; validation must fail if any of those values diverge.
